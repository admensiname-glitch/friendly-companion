# Quality gates for academic questions

## Mandatory duplicate audit

This is a non-negotiable release rule for Ensina-me: no question, exercise, assessment, or course content containing questions may be published or delivered to a student until it passes a duplicate audit.

The audit must evaluate the complete set that will be delivered together and compare:
- exact and normalized wording (case, accents, punctuation, whitespace);
- semantic intent and the learning objective being assessed;
- expected answer / key concept, including objective alternatives and discursive rubric;
- scenario variants that still require substantially the same answer.

Different wording is not proof of uniqueness. Questions assessing the same objective and requiring essentially the same answer count as duplicates and must not appear together in one exam.

If a duplicate is found, replace the question with one assessing a distinct objective and audit the complete exam again. If the audit fails, is inconclusive, times out, or cannot run, fail closed: do not create or deliver the exam. Do not silently bypass the gate.

The same policy applies to new courses and newly authored/imported question banks, before publication. Exam-time auditing is still mandatory because different sources can introduce overlap.

## Required tests before release

- exact duplicate;
- duplicate differing only by case, accents, punctuation, or spacing;
- paraphrased question with the same expected answer / learning objective;
- similar scenario but a genuinely different learning objective (must not be falsely rejected);
- generated question duplicating an existing bank question;
- audit service unavailable or inconclusive (delivery must be blocked);
- duplicate discovered after replacement (audit must run again).
